# Troubleshooting (Miles)

Problems new in GRADUS II. For anything you also set up in Tiro —
installs, Husky, Vite, pytest configuration, CORS, Coverage Gutters —
see **Tiro's `guide/troubleshooting.md`** too.

**First:** read the failing test's **name** and its **assertion
message**. Provided tests are named after the behavior they check.

---

## Backend

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ConnectionRefusedError` / connection refused on port **5434** | Miles's database isn't running | `docker compose up -d --wait` at the repo root |
| `Bind for 0.0.0.0:5434 failed: port is already allocated` | Another copy of Miles (e.g. a fresh clone) is running | `docker compose down` in the other copy |
| `database "miles_test" does not exist` | The init script didn't run — the volume existed before the script was added | `docker compose down -v`, then `up -d --wait` (**deletes dev data**) |
| Every test errors during collection, even `test_config.py` | `conftest.py` is in `tests/` but `app.main` / `app.models` don't exist yet | Copy test files in the order lesson 02 gives. Temporarily move `conftest.py` out until Step 3 |
| `POST /applications` returns `307`, or the body arrives empty | The collection route is `"/"` under a prefix, so the real path has a trailing slash | Use `@router.post("")` and `@router.get("")` |
| Routes missing from `/docs` / tests get `404` for every endpoint | Router not included | `app.include_router(...)` in `main.py` |
| `"   "` is accepted as a company name | Constraints not applied, or `min_length` missing | `Annotated[str, StringConstraints(strip_whitespace=True, min_length=1, max_length=100)]` |
| `test_config` passes alone but fails in the full run | A module read the env var once at import (a constant) | Read the environment *inside* the function each time |
| A `DATABASE_URL` / `TEST_DATABASE_URL` / `FRONTEND_ORIGIN` from your terminal breaks tests | Your shell has the variable set | `unset DATABASE_URL TEST_DATABASE_URL FRONTEND_ORIGIN` (Git Bash) and rerun |
| `RuntimeWarning: coroutine ... was never awaited`, or a change isn't saved | A missing `await` | Await every `db.get`, `db.scalars`, `db.commit`, `db.refresh`, `db.delete`, and your own async helpers |
| `MissingGreenlet: greenlet_spawn has not been called` | Code touched a related object (usually `application.company`) that was never loaded | `lazy="selectin"` on `Application.company`; after a commit, `await db.refresh(application, ["company"])` (lesson 03, "Loading related objects") |
| `test_an_application_loads_its_company` fails with `MissingGreenlet` | `Application.company` uses the default lazy loading | Add `lazy="selectin"` to that relationship |
| Moving an application to another company still returns the old company | The relationship wasn't reloaded after `company_id` changed | `await db.refresh(application, ["company"])` after the commit |
| Error mentioning **greenlet** at import or first query | SQLAlchemy installed without its asyncio extra | `uv add "sqlalchemy[asyncio]"` |
| Response has `company_id` and the test fails comparing dictionaries | `ApplicationRead` still includes `company_id` | Remove it; the response nests `company` instead |
| `company` in the response is `null` or errors | `CompanyRead` lacks `from_attributes`, or the relationship isn't defined | Check both schemas and both `relationship(...)` lines |
| `Mapper ... has no property 'company'` | `back_populates` names don't match | `Company.applications` must say `back_populates="company"`; `Application.company` must say `back_populates="applications"` |
| Duplicate company returns `500` | The unique constraint fired, but nothing turned it into a `409` | Check for an existing name first (lesson 03, Step 3) |
| Autogenerated constraint has name `None`, or the primary key isn't `pk_applications` | Naming convention not on `Base.metadata` | Set `metadata = MetaData(naming_convention=...)` in `Base` (lesson 02, Step 2) |
| `alembic upgrade` fails with *column "company_id" … contains null values* | The database already has applications without companies | `uv run alembic downgrade base`, then `upgrade head` (lesson 03, Step 5) |
| `Target database is not up to date` when autogenerating | The database isn't at the latest migration (e.g. right after `downgrade base`) | `uv run alembic upgrade head` first |
| Alembic uses the wrong database | `env.py` isn't overriding the URL | `config.set_main_option("sqlalchemy.url", get_database_url())` right after `config = context.config` |
| Alembic fails with a sync-driver error (e.g. *psycopg2 not found*) | `env.py` came from the default (sync) template | Re-initialize with `uv run alembic init -t async migrations` (move your old `versions/` files across) |

## Frontend

| Symptom | Cause | Fix |
| --- | --- | --- |
| `api.test.ts`: *Unexpected end of JSON input* | Your code calls `.json()` on the `204` | Return early when `response.status === 204` |
| `api.test.ts`: expected `'Company not found'`, got `'Request failed: 422'` | The error body isn't read, or `detail` isn't checked as a string | See lesson 04, Hint 2 |
| `api.test.ts`: URL is `…/applications?status=undefined` | The query string is added even when no status is given | Only add it when `status` is truthy |
| `import.meta.env.VITE_API_URL` is `undefined` in the browser | No `.env` file, a typo, or a missing `VITE_` prefix; or the dev server wasn't restarted | Copy `.env.example` to `.env` and restart `npm run dev` |
| `Type 'string' is not assignable to type 'Status'` | `event.target.value` is a plain string | Assert it: `event.target.value as Status` (lesson 05) |
| `React Hook "useState" is called conditionally` | An early `return` comes before a hook | Move every hook above the early return |
| `App.test.tsx`: *Found multiple elements with the role "alert"* | More than one error element rendered | One `error` state, one `role="alert"` element |
| `App.test.tsx`: *Unable to find role "alert"* after a failure | The handler has no `try`/`catch`, or the error is set but not rendered | Wrap the `await` in `try`/`catch` and render `error` |
| `App.test.tsx`: a mock returns `undefined` | That test didn't set a return value for a mock `App` calls | Every API function `App` calls on load must be given a value in `beforeEach` — check you haven't added a new one |
| `App.test.tsx`: filter test fails | `fetchApplications` isn't called again when the filter changes | Put `filter` in the effect's dependency array |
| Warning: *An update to App inside a test was not wrapped in act(...)* | A state update landed after the test's last `await` | Usually harmless. Make sure the test awaits the result it checks (`findBy…` or `waitFor`) |

## Still stuck?

1. Re-read the lesson's **contract** — most failures are a label, name,
   or shape that doesn't match exactly.
2. Add `screen.debug()` (frontend) or `print(response.json())` (backend)
   inside the failing test to see what your code actually produced.
3. Run just that one test: `uv run pytest -k <name>` or
   `npm test -- <file>`.
